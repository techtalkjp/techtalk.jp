# 問い合わせ分類の並行評価

既存LLMが通知・返信の判断を続け、軽量モデルは比較結果だけをD1に記録する。
営業(sales)だけが停止対象で、normalとgrayは通知される。
軽量モデルの失敗・評価保存の失敗は通知判断に影響しない。
外部推論APIは追加せず、Workers内のJavaScriptで実行する。
並行評価中は既存LLMを全件呼ぶため、推論費用は減らない。

## 初期モデル

文字2〜4-gramの有無を既知特徴数の平方根で正規化し、L2正則化付き3クラスsoftmax回帰で分類する。
学習と推論は `text-features.ts` の前処理を共用する。
初期モデルは `scripts/inquiry/bootstrap.json` の合成例文28件から学習した試作品。
`holdout.json` の合成例文12件は学習やパラメータ調整に使っていない。
初回結果は8/12一致。実問い合わせの精度を示す値ではない。
実データに適合させるには、人が確認した正解で再学習する必要がある。

入力は本文の先頭500 UTF-16文字で、D1の既存 `message_excerpt` と一致する。
名前・会社名・メールアドレスはモデル入力に使わない。
既存LLMは名前・会社名・先頭1000文字を使うため、同一入力条件の比較ではない。
本文後半に判断材料がある場合は、この差も誤判定の原因になる。
`ml_score` は未校正のsoftmaxスコアで、正解率でも既存LLMの確信度と同じ尺度でもない。
未知語だけ・空本文はgrayとし、スコアは0にする。
モデル版は学習入力・重み・設定のハッシュを含む。

## 記録と評価

`inquiry_evaluations` に `ml_verdict / ml_score / ml_model / ml_error` を追加する。
過去の行はNULLのままで、新しい問い合わせから記録する。
`human_verdict / human_labeled_at` は人が付ける正解。
正解は「送信者がこちらに売る=営業」「こちらへの発注等=normal」「目的不明=gray」。
抜粋だけでは判断できないときは、元メールを確認するか正解を未設定のままにする。
既存LLMの判定をそのまま人の正解としてコピーしない。

```sh
# 未ラベルを先に並べ、本文抜粋と両モデルの判定をローカルへ保存
pnpm run inquiry:manage -- export
# 人が内容を確認して正解を付ける（idは実際の行ID）
pnpm run inquiry:manage -- label 123 normal
# モデル版ごとの集計。本文・個人情報は出力しない
pnpm run inquiry:manage -- report
```

既定は本番D1。ローカルDBでは末尾に `--local` を付ける。
exportには私的な本文が含まれるため、既定保存先 `.tmp/*.private.json` はgit管理外で、権限600にする。
exportファイルは編集してもD1に自動反映しない。labelコマンドで明示的に保存する。
CLIには問い合わせ本文・APIキーを引数として渡さない。

集計は既存LLMとの一致率と、人の正解に対する精度を別々に出す。
正解未設定の行から正解率は計算しない。
営業の適合率・再現率、正当な問い合わせを営業として止める割合、3クラスの混同行列を表示する。
母数0の指標はnull。少数件の数字から本番振り分けへ切り替えない。
既存LLMの成否は `llm_succeeded` に記録する。失敗・成否不明の行は一致率と両モデルの比較から除く。
正常応答で確信度が0の場合は除外しない。以前のWorkflowが保存済みの判定を再利用し成否を持たない場合はNULLにする。
現在モデルの学習に含まれたIDは、人の正解を使う評価から除く。
比較用の判定は受信時に固定して保存し、再学習しても過去の予測を書き換えない。
誤り候補だけでなく、ランダムに選んだ一致例も正解を付ける。偏ったラベル集合の集計は受信全体の正解率ではない。

## 再学習

```sh
# 人の正解が付いた行だけを保存（source=human）
pnpm run inquiry:manage -- training
# 3クラスすべての例が必要。実際の版へ変える前に未使用データで評価する
pnpm run inquiry:train -- .tmp/inquiry-training.private.json
pnpm run validate
pnpm run build
```

再学習はローカルで行い、生成した `text-model.ts` をレビューして通常のWorkerデプロイで反映する。
自動学習・自動切替はしない。
生成物には特徴語（本文の断片）が含まれるため、実メールで学習したモデルをGit公開する前に個人名や機密語の混入を確認する。
初期モデルの再生成は引数なしの `pnpm run inquiry:train`。
合成holdoutの判定を再現するには `pnpm run inquiry:evaluate` を使う。本文は出力しない。
合成例文の再現性テストは、実学習モデルへ切り替えてもbootstrap学習の決定性を検証する。

## 導入順序

`0005_inquiry_ml_shadow.sql` を本番D1へ適用してからWorkerをデプロイする。
既存の列・行は変更しない。
戻す場合はWorkerを以前の版へ戻せば、追加列を残したまま既存LLMだけで処理できる。
実問い合わせを送って動作確認すると通知・返信が発生するため、確認には隔離したWorker/DBを使う。
